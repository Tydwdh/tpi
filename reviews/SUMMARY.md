# 全书审阅汇总：跨章结论

以《深入理解 AI Agent》（10 章全文）为基准审阅 TPI 的完整结论。各章细节见 `chapter01.md`–`chapter10.md`。

## 一句话结论

TPI 是书中「Coding Agent = 七核心工具 + 文件系统」范式的忠实实现，落在书中「大多数 Agent 应用不需要训练/不需要多 Agent」的判断分支；**最亮的是故障处理与可靠性（四层故障分类学逐层落地、崩溃恢复、可重建投影）**，**最缺的是第二视角审查与状态感知（Sidecar/审批、状态栏、来源标记）**。

## 跨章反复出现的同源差距（按优先级排序）

## 已确认的强项（勿退化）

1. **故障处理范本级**（ch5）：四层故障分类逐层落地 + 恢复分级 + 熔断 + 全局上限。
2. **轨迹可靠性**（ch1,3,5）：append-only 事件日志、崩溃恢复不自动重跑、可重建投影、P0-2 原子提交。
3. **工具层**（ch4）：参数保真、路径边界、感知工具输出控制（分页/显式截断/artifact 落盘）、可观测性。
4. **压缩保留优先级与书中对齐**（ch2）：SUMMARY_SCHEMA 9 字段覆盖书中 1–5 条。
5. **单 Agent 定位符合书中判据**（ch7,10）：纯 Harness 路线 + 工具执行反馈新信息，无需训练/多 Agent。

## 关于「合理缺席」的说明

以下缺失经对照判定为合理（书中明确支持或场景不适用），**不建议**为 TPI 引入：

- 训练/微调栈（ch7：大多数应用不需要训练）
- 多 Agent 协作/子 Agent（ch10：无新信息则不值得；单 Agent 已获执行反馈增量）
- MCP 生态（ch4：书中 Pi 派——内置工具自审计，安全面更小）
- 语音/Computer Use/机器人（ch9：纯文本终端定位）
- 用户记忆/RAG（ch3：coding agent 场景，AGENTS.md + grep 已覆盖）
- 自动持续进化（ch8：用户即人工进化循环）

## 建议下一步

若只做一件事：**① 状态栏 + ② 来源标记**（差距 2、3）——两个改动都小、都直接命中书中反复强调的「上下文质量决定能力」与「提示注入分层防御」，且相互独立可单独实施。
