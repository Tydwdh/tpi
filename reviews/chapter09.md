## 2. 亮点（文本 Agent 的多模态边缘）

1. **流式交互已是文本版终点**：TPI 的 SSE 流 + TUI 增量渲染（thinking delta / text delta / tool output delta）对应书中「ASR/LLM/TTS 各阶段流式」的 LLM 环节——用户实时看到思考与输出，无轮次等待。
2. **web_fetch = 「提取为文本」路线**：书中多模态感知三路径之一（纯文字内容用文本提取），对纯文本模型是正确选择；html2text 保留结构（表格/链接标题），layout 敏感场景（图）明确不适用。
3. **「观察→动作→验证」哲学贯穿**：书中 Computer Use 骨架「模型只提出候选动作，不能凭上一轮文字宣称跳过新观察」——TPI 的 ReAct 每轮工具结果回填后再决策、eval 验收独立于模型声明，同一纪律。
4. **反爬处理**：web_search 多引擎回退（DDG→Bing→Yahoo）处理人机验证页，不静默降级——对应书中「生态壁垒/CAPTCHA」的文本版应对。

## 3. 差距与建议

### 3.1 无多模态输入（合理缺席，但值得记录边界）

- TPI 纯文本：read 只读文本、web_fetch 转文本。若未来需要理解截图/PDF 图表，最小路径是「工具化」路线（把多模态模型封装为工具，如截图 OCR 工具），而非改 provider 支持图像输入——与书中「工具化模式」一致，不动核心架构。

### 3.2 无实时/主动交互（设计边界）

- 书中语音/Computer Use 强调「持续感知、随时被打断」；TPI 是「用户发起 → run 直到结束」的同步交互，取消靠 Esc/cancel token。
- 评估：对终端 coding agent 正确（用户在场、任务边界清晰）。若未来要支持「长任务完成后通知/唤醒」，需引入第四章事件驱动架构（超出当前范围）。

## 4. 反叙事设计备注

**无全双工/实时是定位而非落后**：书中语音篇幅最长是因它是「演进线走完整」的参考系；TPI 的文本终端交互不需要该演进线——它的「交互闭环」是纯文本的，已用流式 + 即时反馈达到该形态的实用终点。
